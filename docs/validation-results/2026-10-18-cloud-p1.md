## 実行条件

[実装計画の先行可能範囲](../implementation-plan.md#依存関係)に限定します。実機への導入、USB 待ち受け、画面の取り込み、MediaCodec と Surface による表示は実施しません。合成入力の確認を 2184×1968 / 60fps の表示達成とは扱いません。

プロジェクトの初期化と Wrapper 生成には Gradle の標準タスクを使用しました。Wrapper は公式の `gradle/gradle-distributions` GitHub 配布へ固定し、ZIP と JAR の SHA-256 を[公式チェックサム一覧](https://gradle.org/release-checksums/)と照合しています。

- 配布 ZIP: `f397b287023acdba1e9f6fc5ea72d22dd63669d59ed4a289a29b1a76eee151c6`
- Wrapper JAR: `2db75c40782f5e8ba1fc278a5574bab070adccb2d21ca5a6e5ed840888448046`

コアの依存は Maven Central から取得し、Gradle が生成したロックファイルを使用します。Android の依存は Google Maven の名前解決エラーで取得できず、Android 用ロックの生成・APK の検査もできていません。

次の通常コマンドと、その末尾に `--offline` を追加したコマンドの両方で clean ビルドと計 37 件のテストが成功しました。失敗・スキップは 0 件です。作業ディレクトリはリポジトリルートです。どちらも依存取得済みのキャッシュを使用しており、空キャッシュからの全ダウンロードの証拠ではありません。

```sh
FFMPEG=/usr/bin/ffmpeg ./gradlew -p core clean build ffmpegIntegrationTest --configuration-cache
```

Android 側では次を試みましたが、Google Maven から AGP を取得できず失敗しました。これは検証済みビルド手順ではなく、ネットワーク復旧後に再試行が必要な記録です。

```sh
./gradlew test lint assembleDebug --write-locks
```

合成映像は Gradle の `generateFfmpegFixtures` タスクが `lavfi testsrc2`、`libx264`、`yuv420p`、B フレームなし、AUD・反復ヘッダーありで生成します。全分割位置・1 バイトずつの分割でアクセスユニットを比較し、AUD を除去した場合の拒否も確認します。生成物は `core/build/` 内だけに置き、通常の `test` には合成映像テストを混ぜず、明示的な `ffmpegIntegrationTest` で実行します。

生成ファイルを次のコマンドでも手動確認しました。

```sh
ffprobe -v error -count_frames -show_entries stream=codec_name,width,height,r_frame_rate,avg_frame_rate,nb_read_frames:frame=pkt_duration_time -of default=noprint_wrappers=1 core/build/fixtures/synthetic.h264
```

観測は H.264、64×64、3 フレーム、各 `pkt_duration_time=0.200000` 秒でした。ただし raw H.264 のこの解析では `r_frame_rate=10/1`、`avg_frame_rate=25/1` と表示されました。生成指定の 5fps とも異なるため、これらの推定値を実測 fps や実表示性能として採用しません。

## 制限・気づき

- P0 の実機ゲートは未完了です。単体テストや APK 生成によって導入許可・USB 到達性・実機デコードの問題を解消したとは扱いません。
- AUD などの先行検証の入力条件は仮契約であり、両 PC の FFmpeg 出力で確認してから固定します。ビットストリーム全体の正当性を境界解析だけで保証しません。
- 仮契約は各 AU の先頭に AUD、新規セッションの初回 AU に SPS/PPS と IDR を必要とし、メタデータはスライスの前に置きます。対応 NAL は 1 / 5 / 6 / 7 / 8 / 9 です。長いゼロ列など対応しない Annex-B 表現も拒否します。任意のスライス途中切断、SPS/PPS とスライスの整合、同一ピクチャへの所属までは解析していません。
- 現在の上限は NAL 256KiB（開始コード除外）、AU 1MiB（正規化した開始コード込み）、128 NAL/AU、キュー 2 AU、無通信 5 秒、統計窓 1 秒です。実機の対象解像度に適切な値かは未確認で、正式な送信条件ではありません。具体的な定義・境界の期待値はコードとテストを正とします。
- セッションと診断値は単一所有スレッドのモデルです。解除コールバックの一度だけの実行をテストしていますが、実ソケットの停止や Android 資源の解放は未検証です。診断値はアプリ内処理時間や総遅延を測定せず、パネル提示数も意味しません。
- 性能基準 Q07 は未合意です。総遅延・実表示 fps・発熱・連続稼働は未測定です。

## 再開条件と引き継ぎ

1. 許可されたネットワークで Google Maven と Android Developers の公式資料にアクセスできる環境を用意し、AGP の互換条件・採用 SDK の権限条件を再確認します。非公式ミラーやセキュリティ設定の無効化で回避しません。
2. 上記の Android タスクを再試行し、依存ロックを生成・レビューします。生成 APK の権限・識別子・版を検査した後、許可された端末での導入・起動を別結果として記録します。署名鍵・APK はコミットしません。
3. [P0 の実機引き継ぎ](2026-10-18-cloud-p0.md#実機環境への引き継ぎ)を完了します。両 PC の H.264 出力を仮契約と比較し、AUD・構成情報・スライス・各上限の妥当性、MediaCodec 互換性を実証して P1 を完了させます。
4. P2 以降の実機表示・復旧・受け入れは、その完了後に進めます。今回のコアの状態制御を実ソケット・前景・Surface へ結合する実装は残っています。
