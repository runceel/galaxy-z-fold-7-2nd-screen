## 実行条件

リポジトリとローカル環境を読み取り調査しました。版表示には `java -version`、`gradle --version`、SDK 内の `adb version` を使用し、SDK の版は各パッケージの `source.properties` から確認しました。OS は `uname -srm` と `/etc/os-release`、ネットワークインターフェイス名は `/sys/class/net` で確認しました。

`adb` は版表示だけに使用し、接続・転送・logcat は使用していません。USB テザリングに相当する接続は確認できておらず、ローカルネットワークでの代替疎通も実施していません。ドライバー導入、ネットワーク設定変更、受信ポート公開、映像生成・転送は行っていません。解像度・fps・ビットレートの実測値はありません。

## 制限・気づき

- Android 開発ツールの追加だけでは、Windows の VDD / 取り込み / エンコード、Fold の USB 限定待ち受けの成立性を実証できません。
- エミュレーターや Linux の合成映像で成功しても、P0 の対象実機ゲートを置き換えられません。このため P1 のプロジェクト作成には進んでいません。
- 管理ポリシーは不明であり、許可済みとも禁止とも判定していません。制限回避やセキュリティ設定の無効化は行っていません。

## 実機環境への引き継ぎ

次の項目は**未実施の確認事項**であり、検証済みの操作手順ではありません。[P0 の作業と完了条件](../implementation-plan.md#p0-環境成立性の確認)、[初回準備](../operations.md#初回準備)に従い再開してください。

1. Windows Arm64、AMD CPU 搭載 Windows x64、同じ Fold7、USB データケーブルを用意します。各 PC と Fold で USB テザリング・APK・署名済み既製ドライバー導入の許可を確認します（Q01）。禁止なら中止します。
2. 各 PC の OS、GPU とドライバー、VDD / FFmpeg の取得元と版を記録します。識別用の非機密画像で拡張画面の取り込みと 2184×1968 の H.264 生成を確認し、実際のエンコーダーと出力条件を記録します（Q02・Q03、T01・T12 の P0 範囲）。元資料のコマンドは未検証のままです。
3. 許可された検証用アプリ等で、開発者モード無効時の導入済みアプリ起動と USB 側アドレスへの限定待ち受けを確認します。PC からの接続、許可された他インターフェイスへの非公開、USB 再接続時のアドレス変化を記録します（Q04、T02・T03 の P0 範囲）。全インターフェイス待ち受けで代替しません。
4. 通常回線あり・なしの実経路と携帯回線利用の可能性を確認し、変更した設定の復元も記録します（Q09、T11）。モバイル通信を許容できず経路が不明なら開始しません。
5. 性能基準案の採否を利用者と合意し、変更時は理由を残します（Q07）。両 PC の P0 結果を環境別に記録し、完了条件を満たしてから P1 へ進みます。

P0 のファイル生成・疎通確認は P4 の全試験成功を意味しません。P1 では両 PC の非機密な出力サンプルと圧縮条件を使って映像契約を実証し、SDK・JDK・Gradle の公式な互換性を確認してビルド基盤を固定します。
