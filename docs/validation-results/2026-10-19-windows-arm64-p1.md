## 実行条件

[先行可能範囲](../implementation-plan.md#依存関係)の開発基盤を検証し、後続で利用者が許可した接続中の端末に検証用 APK を導入・起動しました。後続確認は P0 の導入可否確認の一部であり、P1 の実機映像契約や P2 には進んでいません。USB 待ち受け、画面取り込み、MediaCodec、Surface は未実装・未検証です。ビルド対象の Activity は独立検証用の説明を表示するだけです。

[AGP 8.7 の公式互換条件](https://developer.android.com/build/releases/agp-8-7-0-release-notes)は最大 API 35、Gradle 8.9 以上、Build-Tools 34.0.0、JDK 17 です。採用済みのバージョンを変更せず、その構成でビルドしました。

初期状態の JDK 25.0.3 では Gradle の設定処理が `25.0.3` というエラーで停止しました。既存 JDK 21 に切り替えると Google Maven の AGP 解決は進みましたが、SDK の場所が未指定で停止しました。既存 SDK を指定した試行では Build-Tools 34.0.0 と承認済みライセンスがなく停止しました。既存 SDK は読み取り専用の警告も出したため変更していません。

利用者の SDK 利用許諾への同意と導入承認を得て、作業専用フォルダーに SDK を導入しました。JDK 17 もシステム設定を変更せず同フォルダーに展開しています。[Microsoft 公式配布](https://learn.microsoft.com/en-us/java/openjdk/download)の ZIP と公開 SHA-256 を照合しました。

- JDK ZIP: `microsoft-jdk-17.0.20.1-windows-aarch64.zip`
- SHA-256: `6872e702181fe88773a80bc3684281c111091e29e7f190ac5af06b0315f8b849`

環境変数だけを変更して再利用した Gradle daemon では旧 SDK を参照する試行があったため、以降は `--no-daemon` で単発プロセスを使用し、`ANDROID_HOME` と `ANDROID_SDK_ROOT` を同じ SDK に揃えました。原因の一般化はしていません。永続的な環境変数、管理ポリシー、ネットワーク、ドライバー、端末設定は変更していません。

作業ディレクトリはリポジトリルートです。JDK 17 のルートを `JAVA_HOME`、作業専用 SDK のルートを `ANDROID_HOME` と `ANDROID_SDK_ROOT` に設定して実行しました。依存ロック生成時だけ、次の通常コマンドに `--write-locks` を追加しました。

```powershell
.\gradlew.bat clean test lint assembleDebug --no-daemon --configuration-cache --console=plain
.\gradlew.bat clean test lint assembleDebug --offline --no-daemon --configuration-cache --console=plain
```

両方とも成功しました。通常の単体テストは計 34 件です。Android アプリには単体テストがなく、アプリのテストタスクは `NO-SOURCE` でした。Android のコンパイル・Lint・APK 生成と、JVM コアの単体テストを区別します。configuration cache の保存を確認しましたが、再利用の性能評価はしていません。依存の一部は事前の試行で取得済みで、空キャッシュからの全取得の証拠ではありません。

標準の `.\gradlew.bat build --offline --no-daemon --configuration-cache --console=plain` も成功し、release 側を含む通常のビルドで strict ロックが不足しないことを確認しました。ここで生成された未署名の release APK は導入用に採用せず、以下の内容検査は debug APK だけを対象としています。

最終の offline Lint はエラー 0、警告 2 件（`DataExtractionRules`、`MissingApplicationIcon`）でした。初回のオンライン実行では AGP 更新案内も 3 件出ています。警告は抑制しておらず、警告なしとは扱いません。今回のアプリは永続データを持たない検証用の説明画面に限定します。

生成物は `app/build/outputs/apk/debug/app-debug.apk`（2,374,121 bytes）です。SDK の `aapt dump badging` と `aapt dump permissions` で次を確認し、`apksigner verify` が終了コード 0 で成功しました。

- 識別子・版・SDK は上記の設定と一致し、起動 Activity は `dev.fold7.validation.MainActivity`。
- debuggable な debug APK であり、実運用向けの署名済みリリースではない。
- 要求権限はなし。`INTERNET` を含まない。
- APK SHA-256: `306c17991b2cf3c44b08a043344ff40b2a196b57ee7a18db26af22efe30d1600`。今回の生成物の識別用であり、別環境の debug 署名で同一ハッシュになる保証ではない。

コア専用の次の実行も成功しました。このとき SDK 環境変数は設定していません。

```powershell
.\gradlew.bat -p core clean build --offline --no-daemon --configuration-cache --console=plain
```

## 制限・気づき

- Windows Arm64 ホストでのビルド成功であり、全ツールが Arm64 ネイティブで動作することや、AMD x64 環境での再現性を示しません。
- 後続確認で検証用 APK の導入・説明画面の起動は確認しましたが、Android 上の自動テストは未実施です。Android 16 以外での起動、ローカルネットワーク権限、USB 限定待ち受け、デコーダー互換性は未確認です。
- [ローカルネットワーク保護の公式資料](https://developer.android.com/privacy-and-security/local-network-permission)では受信 TCP 接続も対象です。Android 16 の opt-in と、Android 17 / target 37 以上の必須化を区別し、実機 OS と採用 target に応じた条件を結合前に確認します。今回は通信せず、権限も追加していません。
- ビルド用 JDK・SDK と APK はローカルの開発用生成物として保持し、Git に含めません。署名鍵もコミットしません。SDK の導入を端末への導入許可と混同しません。
- P0、Q01〜Q07・Q09、T01〜T12 と性能の合意・実測はこの結果では解消しません。P2 以降へ進む条件も変更しません。
