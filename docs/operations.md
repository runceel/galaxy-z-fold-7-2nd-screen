# セットアップ・運用

## 状態

これは実装・実機検証前のチェックリストです。インストール方法、APK の生成コマンド、送信コマンドの確定版はまだありません。[元の引き継ぎメモ](../fold7-submonitor-handover.md)のコマンドを検証済み手順として実行しないでください。P0〜P5 で確認できた情報をこの文書へ反映します。

## 初回準備

1. 管理者・端末ポリシーを確認する。USB テザリング、APK の手動導入、既製ドライバーの導入が禁止される場合は作業を止める。
2. 両 PC の OS、アーキテクチャ、GPU を確認する。VDD と FFmpeg は取得元、版、対応アーキテクチャ、必要権限を記録してから導入する。
3. VDD の既存設定を退避し、2184×1968 の拡張画面を設定する。Windows の表示番号と FFmpeg の取り込み番号が同じとは仮定せず、識別画像で確認する。
4. 対象 PC のエンコーダーで短いファイル出力を確認する。元資料のコマンドは、フィルター、入力形式、エンコードオプション、GPU の整合性を確認してから採用する。
5. 許可された方法で APK を導入する。開発者モードが使える短時間の adb 導入は任意とし、常用時は依存しない。開発者モードなしの手動導入が許可されるかも確認する。
6. USB テザリングのアダプターと Fold のアドレスを確認し、待ち受けを USB 側へ限定できることを確かめる。

外部ドライバーにも適切な署名・導入許可が必要です。個人用 APK にも署名が必要で、更新時には署名の継続性が必要です。秘密鍵をリポジトリに置きません。

## ネットワーク設定の注意

アダプター名や Fold の IP を固定値として扱いません。USB 用アダプター、IPv4 / IPv6 のアドレスとルート、PC から Fold への実際の経路を確認します。デフォルトゲートウェイは候補であり、実際の受信アドレスと到達性を確かめます。

テザリング側のメトリックを大きくする方法は候補ですが、通常回線が切れると携帯回線へ流れる可能性があり、モバイル通信の完全な防止策ではありません。管理ポリシーの範囲内で、通常回線あり・なしの挙動を確認します。通信量を絶対に発生させてはいけない場合は、未検証の経路設定に頼らず、使用を開始しません。

変更する前に、対象アダプター、アドレスファミリー、自動メトリックの有効状態、メトリック値を記録します。終了後は記録した値へ戻します。名前のワイルドカードだけで複数アダプターを一括変更しません。

ファイアウォールの全面無効化、セキュアブート無効化、端末管理制限の回避は行いません。

## 日常の開始手順

1. Fold を開き、USB データ通信可能なケーブルで接続し、許可された USB テザリングを有効にする。
2. Windows の拡張画面、解像度、取り込み対象とネットワーク経路を確認する。USB 再接続後はアドレス変更にも注意する。
3. アプリを前景で起動し、USB 側の待ち受けアドレスとポート、待機状態を確認する。
4. 対象 PC で検証済みの FFmpeg コマンドを実行する。アプリを起動する前に送信を始めない。
5. 映像、向き、カーソル、状態表示を確認する。表示 fps と低遅延機能の有効状態を確認し、黒画面やエラーを正常と扱わない。

送信コマンド確定時には、対象 PC、FFmpeg 版、GPU、取り込み対象、解像度、fps、圧縮方式、接続先、アクセスユニットの条件を併記します。

## 終了と復旧

- 通常終了: FFmpeg を停止し、アプリで切断・待機を確認してから終了する。USB テザリングを止め、必要に応じて仮想画面を無効化し、変更したネットワーク設定を復元する。
- 映像が止まった: アプリのエラーと FFmpeg の終了理由を確認する。無通信ならセッションが解放されることを確認し、待機状態に戻ってから送信を再開する。
- USB 抜き差し後: USB 経路と Fold のアドレスを再確認し、待ち受けを再開してから FFmpeg を起動する。
- 黒画面: 対象画面、GPU の整合、構成情報・キーフレームの到着、デコーダーエラーを順に確認する。ファイアウォールやポリシーを無効化して解決しない。
- 低 fps・遅延: 実際のエンコーダー、CPU / GPU 負荷、入力・表示 fps、受信量、キュー、端末発熱を確認する。30fps への変更は切り分けとして記録し、60fps 達成とは扱わない。

復旧にアプリ再インストールや端末再起動が必要な場合は、通常手順に組み込まず不具合として記録します。adb を使えない状態でも確認できる情報で記録してください。
