# 検証計画

## 判定方針

Windows / Fold 実機の実測結果はありません。自動テストで保証する処理と、Windows / Fold 実機が必要な項目を分けます。P1 の独立検証は[実装計画の例外範囲](implementation-plan.md#依存関係)だけで先行し、試験不能は成功ではなく未確認と記録します。

参照: [要求仕様](requirements.md)、[実装計画](implementation-plan.md)。

## 環境マトリクス

| 環境 | 用途 | 必須の確認 |
| --- | --- | --- |
| Windows Arm64 + Fold7 | 実運用 | VDD、実際の取り込み、利用可能なエンコーダー、USB 経路、60fps、復旧 |
| AMD CPU 搭載 Windows x64 + 同じ Fold7 | 実運用 | 実 GPU に応じた圧縮、GPU の整合、上と同じ受け入れ |
| 開発用 x64 PC + Android エミュレーター | 任意の補助 | UI、基本ライフサイクル、開発用映像疎通。実機の性能・低遅延機能・USB 到達性の判定には使わない |

PC ごとに FFmpeg、VDD、OS、GPU ドライバー、コマンド、解像度と表示スケールを記録します。Fold では OS、アプリ版、低遅延機能の対応、表示向きを記録します。APK は両 PC で同一のものを使います。

## 機能と異常系

| ID | 対応要求 | 試験 | 合格条件 |
| --- | --- | --- | --- |
| T01 | R01、R02、R11 | 両 PC に拡張画面を作り、専用の識別画像を送る | ミラーではなく対象の拡張画面だけが 2184×1968 で表示される |
| T02 | R03、R06、R12 | USB 経由の接続と待ち受け範囲を確認する | USB 側から到達し、許可されない他インターフェイスには受信口を公開しない。調査できない経路は未確認とする |
| T03 | R04 | 開発者モードを無効にして起動、接続、切断、再接続 | adb / logcat なしで完結する |
| T04 | R05、R07 | 向き、画面端、余白、カーソル、点灯を確認する | 変形がなく、PC 操作を表示できる。入力転送はなく、表示終了後は点灯維持を解除する |
| T05 | R08 | 映像停止・破損・低遅延機能非対応を発生させる | 待機と失敗を区別し、理由と復旧操作を表示する。測定できない値を 0 や成功として表示しない |
| T06 | R09 | FFmpeg 正常終了・強制終了、USB 抜き差し、再起動 | 古いデータや構成を破棄し、アプリ再起動なしで新映像が出る |
| T07 | R09 | 接続後にデータを送らない、途中で送信を止める | 定義した時間内に無通信として終了し、新規接続を受けられる |
| T08 | R09 | バックグラウンド移行、画面消灯、Surface 喪失・再生成 | 資源を解放し、前景復帰後の再接続で表示できる |
| T09 | R06、R09 | 表示中に 2 本目の接続を試す | 明示的に拒否し、既存表示と状態を壊さない |
| T10 | R02、R09 | 不完全・破損・過大 NAL、構成情報欠落、非対応映像 | 無制限の確保や待機、クラッシュを起こさず、明示的エラーと再接続が可能 |
| T11 | R03、R12 | Wi-Fi 併用、USB 再接続、通常回線切断時の経路を確認する | 送信は USB 経路。PC の既定経路と携帯回線利用の可能性を説明・確認でき、設定を戻せる |
| T12 | R01、R10 | 対応機能の有効・無効、HW 失敗と代替エンコード | 実際に使用した方式を記録し、切り替えを隠さない。各経路でデコード互換性を確認する |

T02 は利用できる許可済み環境から確認します。会社ネットワークの走査や管理設定の回避を行う試験ではありません。

### 実施条件と証拠の点検

各試験で環境・版・APK のハッシュ、操作順序、期待値、観測値、判定を記録します。画面の代わりに非機密の識別画像・動くカウンターを使い、観測できない事項は未確認とします。次の項目は実施前の準備事項であり、検証済み手順ではありません。

| 試験 ID | 用意する条件・観測方法 | 終了時の確認 |
| --- | --- | --- |
| T01 | 両 PC で元の画面構成を控え、拡張画面だけに識別画像を配置。取り込み対象、エンコード出力寸法、Fold 表示を別々に確認 | VDD の有効状態・解像度・画面配置を元に戻す |
| T02 | Fold の USB 側の IPv4 / IPv6 と bind 先、PC の実経路を記録。許可された接続元から USB 到達と他インターフェイスへの非公開を確認。拒否の理由を bind とファイアウォールで混同しない | 受信口が閉じたことを確認。到達試験できなかった経路を列挙 |
| T03 | 導入済みの同じ APK で開発者モード無効を確認。アプリ UI と送信側の出力だけで操作 | 検証のために変更した開発者設定・導入許可を元に戻す |
| T04 | 画面端の枠、円、文字、カーソルを含む画像を使用。OS の通常の消灯条件と比較して点灯維持の解除を確認 | 終了後に点灯維持が残らない。向き・画面設定を復元 |
| T05 | アプリ内の状態・エラー・測定不能表示と送信側エラーを対応付ける。低遅延機能は照会結果と有効化結果を区別 | 破損入力を停止し、正常送信に戻して復旧確認 |
| T06 | 正常終了、強制終了、USB 抜き差し、送信側再起動を個別に実施。再接続後は別の識別画像を使い古い映像の混入を検出 | 正常接続を再確認し、USB アドレス変更を再取得 |
| T07 | 無送信と途中停止を区別し、アプリ版で定めた無通信期限の前後を測定。新接続で表示を確認 | 停止した送信元を終了。終了理由と所要時間を残す |
| T08 | バックグラウンド、消灯、Surface 再生成を個別に実施。接続・デコーダー解放と復帰後の新セッションを確認 | 元の画面設定に戻し、点灯維持と資源残留を点検 |
| T09 | 異なる識別画像の送信を 2 本用意。2 本目の明示的拒否と 1 本目の表示継続を別々に確認 | 2 本とも終了し、次の単独接続が可能なことを確認 |
| T10 | 非機密の小さな異常入力を種類別に使用。入力サイズとアプリ版の上限を記録し、境界ちょうど・超過を区別 | 各ケース後に正常入力で再接続し、メモリ・資源を比較 |
| T11 | 通常回線あり・なし、Wi-Fi 併用、USB 再接続の各条件で IPv4 / IPv6 の実経路を確認。携帯回線利用を許容しない場合は不明な経路で送信しない | 自動メトリック・値・アダプター状態を変更前の記録へ戻し、通常通信を確認 |
| T12 | 同じ動く映像で実際のエンコーダーとデコーダー設定を記録。HW 非対応を成功扱いせず、代替経路は別結果として採取 | 試験用の圧縮・低遅延設定を元に戻す |

T06〜T10 の反復時は、セッション終了後のメモリ・スレッド・ソケット・デコーダー数を同じ測定条件で比較します。JVM のモデルテストだけで Android の資源解放を合格にしません。機器や OS で観測手段が用意できない場合は、その観測項目を未確認として残します。

## 自動テスト

P1 から、Android に依存しない映像処理を重点的にテストします。

- 3 / 4 バイトの開始コードを全分割位置で分割する。複数 NAL・アクセスユニットを 1 回の受信にまとめる場合と比較し、結果が変わらないことを確認する。
- 1 枚に複数スライスを含む映像、AUD の有無、SPS/PPS と IDR、入力末尾、途中切断を扱う。採用しない形式は明示的に拒否する。
- 不正長、未完データの継続、上限ちょうどと上限超過、キュー飽和、無通信時間の境界を確認する。
- セッション終了後に次のセッションへ前回の状態を持ち越さないことを確認する。
- 終了処理が受信待ちを解除し、多重終了でも資源を持ち越さないことを確認する。
- fps / ビットレートの測定窓、接続前と接続後のリセット、測定不能状態の表示を確認する。

実デコーダー、Surface、低遅延機能、OS ライフサイクルは Android 上のテストと手動試験で補います。単体テストのみで実機互換性を保証しません。

### 実機非依存の検証区分

以下の L ID は独立検証用であり、T01〜T12 の合格を意味しません。具体的な入力・上限・期待値はコードとテストを正とし、実行したコマンド・件数・版と制限は環境別の検証結果へ記録します。

| ID | 検証対象 | 確認できないこと |
| --- | --- | --- |
| L01 | Wrapper を使用した Kotlin コンパイル・単体テスト、Android Lint・APK 生成 | 実機への導入・起動・表示、実運用向け署名 |
| L02 | 開始コードの全分割位置、TCP の結合・分割、NAL とアクセスユニットの区別 | 実 PC の出力との契約、MediaCodec 互換性 |
| L03 | 不正・未完・未対応入力、NAL / AU / キューの上限と明示的な失敗 | H.264 全構文の正当性、実デコーダーの安全性 |
| L04 | 単一セッション、無通信期限、多重終了、旧セッションの更新拒否、解除通知 | 実ソケットの待機解除、Android の資源解放・ライフサイクル |
| L05 | 単調時計による測定窓、入力・出力 fps とビットレート、測定不能、リセット | 画面間総遅延、パネル提示数、UI 表示 |
| L06 | FFmpeg の合成 H.264 を使用した AUD・SPS/PPS・IDR・複数スライスの解析 | Windows の取り込み・HW 圧縮、2184×1968 / 60fps の実表示 |

合成映像はテスト時に生成し、受信映像や端末由来のサンプルをリポジトリに保存しません。FFmpeg がない環境で L06 を省略した場合は成功ではなく未実施と記録します。

## 性能・連続稼働

目標は両 PC で 2184×1968 / 60fps です。30Mbps や GOP 60 は元資料の初期候補であり、合格基準ではありません。

以下の数値は**P0 で採否を判断する暫定案**です。採用または変更を記録するまで、正式な性能合格を出しません。

| 項目 | 基準案 | 測定方法 |
| --- | --- | --- |
| 表示 fps | 連続動作するテスト映像で、定常状態の 10 秒窓ごとに平均 58fps 以上 | アプリの表示用出力カウンターで 5 分間記録。実パネルへの提示数とは区別する |
| 画面間の総遅延 | 95 パーセンタイル 100ms 以下 | PC と Fold の両方に同じ時刻表示を写す。120fps 以上の外部カメラ等で 100 サンプル以上採取し、方法と測定誤差を記録する |
| 連続稼働 | 30 分間、クラッシュ・停止・継続的な遅延増大なし | 動画と文字スクロールを含む場面で記録。発熱と終盤の fps 低下も確認する |
| 再接続 | 10 回の切断・再接続すべてで表示再開 | 接続確立から最初の表示までを記録。構成情報とキーフレーム待ちも含める |
| 再開時間 | 有効な送信開始後 5 秒以内に最初の映像 | 待ち受け再開後に FFmpeg を起動。USB 自体の OS 再認識時間は別記する |

総遅延の試験では、拡張画面の内容を PC の物理画面へ比較表示する検証用の手段を用意し、その表示経路の遅れも記録します。測定用の複製が実運用の拡張画面試験を置き換えないようにします。

### Q07 の合意時に決める事項

上表の数値はまだ承認済みではありません。両 PC に適用する以下の条件を利用者と確認し、合意日・採用値・変更理由を検証結果へ記録してから性能の合否を出します。

- fps: 定常状態の開始条件、ウォームアップの扱い、10 秒窓の全窓を判定すること、入力 fps と表示用出力 fps の区別。
- 総遅延: 比較表示の経路、カメラの速度・時間分解能、100 サンプル以上の抽出方法、95 パーセンタイルの算出方法。測定誤差が閾値付近の判定に与える影響。
- 連続稼働: 30 分間の内容、充電・輝度・リフレッシュレート・周囲温度、発熱による停止条件、開始・定常・終盤の負荷と資源測定方法。
- 再接続: 10 回の切断理由の内訳、各回の成功条件。有効な送信開始から最初の映像までと USB の再認識時間を別々に記録する方法。
- 未達時の扱い: 片方の PC、30fps、ソフトウェア圧縮、低遅延機能非対応の結果を分離すること。未達を隠すために測定窓や基準を変更しないこと。

アプリのキュー滞在時間や入出力間の経過時間は、PC の取り込み・圧縮・転送とパネル表示を含まないため、総遅延の代用にはしません。時計の同期なしに別端末間の時刻差を直接計算しません。

CPU / GPU 負荷、受信ビットレート、メモリ、Fold の温度・充電条件も記録します。メモリは開始直後だけでなく定常時と再接続の反復後を比較し、継続増加の有無を確認します。

## 結果の残し方

実測が得られたら `docs/validation-results/` に環境別の Markdown を追加します。最低限、日時、構成と版、実行条件、試験 ID、期待値、実測値、成功・失敗・未確認、制限、再現手順を記録します。機密画面、署名鍵、個人識別情報は保存しません。

性能基準変更で失敗を隠さず、変更理由を残します。両 PC の結果が揃い、必須試験と合意した性能条件を満たして初めて実運用可能と判定します。
